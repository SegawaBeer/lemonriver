**LemonRiver** is a slide framework for the agent era. You describe a deck in
natural language; your coding agent writes the React. LemonRiver handles the
canvas, scaling, navigation, hot reload, present mode, and export so the agent
can focus on content.

Every page renders into a fixed **1920 × 1080** canvas. Slides are arbitrary
React components — not a constrained DSL.

```npm
npx @lemonriver/cli init
```

## Built on open-slide

LemonRiver is a second development of [open-slide](https://github.com/open-slide/open-slide),
the React-first slide framework. It follows upstream releases and carries its own work on top.

What differs from upstream:

- **Renamed throughout.** The packages publish as `@lemonriver/core` and
  `@lemonriver/cli`, the CLI runs as `lemonriver`, and the config file is
  `lemonriver.config.ts`.
- **A story board for a deck.** A deck laid out as chapter columns on a pannable
  canvas — drag a card to reorder, open a page in the editor, write speaker notes
  on a card, or drop a blank page into a column. Cards also take a name, a status,
  a work memo and loose links to other pages, all kept on the board and never
  written into the deck.
- **Workspaces written before the rename keep working.** No edits needed: the old
  package name, the old `open-slide` command, and `open-slide.config.ts` all still
  resolve.
- **Its own version line.** LemonRiver starts at 0.1.0 and tracks open-slide
  upstream. The framework history before the fork is kept alongside the new
  changelog.

Everything else — the canvas, the inspector, present mode, export, and the CLI
subcommands — is upstream's, and tracks it.

## Why LemonRiver

- **Agent-native authoring.** Ships with skills that any Claude Code, Codex,
  or Cursor session can call.
- **In-browser inspector.** Click any element in the dev server to tweak it
  directly in the visual editor, or leave a comment for your agent to apply.
- **Assets manager + svgl.** Drop in images, search 1500+ brand logos through
  the integrated [svgl](https://svgl.app/) catalogue.
- **Professional present mode.** Fullscreen playback, presenter view, speaker
  notes, timer.
- **Export to static HTML or PDF.** Self-contained output — share without a
  server.

## A slide is a file

Each deck lives under `slides/<kebab-case-id>/`. The entry is
`slides/<id>/index.tsx`. Assets sit alongside in `slides/<id>/assets/`.

```tsx title="slides/getting-started/index.tsx"
import type { Page, SlideMeta } from '@lemonriver/core';

const Cover: Page = () => (
  <div style={{ width: '100%', height: '100%', background: '#08090a', color: '#f7f8f8' }}>
    <h1 style={{ fontSize: 188, letterSpacing: '-0.04em' }}>
      Hello, <em style={{ color: '#7170ff' }}>LemonRiver</em>.
    </h1>
  </div>
);

export const meta: SlideMeta = { title: 'Getting started', theme: 'corporate' };
export default [Cover] satisfies Page[];
```

Two rules: the default export is an array of components (one per page), and
each component fills its container (`width: '100%'` / `height: '100%'`).

## The 1920 × 1080 canvas

The runtime scales the canvas uniformly to fit the viewport, so the same
slide looks identical on a phone, a 4K monitor, and a beamer — every pixel
coordinate you write is the coordinate that ships, in preview, present mode,
and export.
